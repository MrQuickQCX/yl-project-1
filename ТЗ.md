# ТЗ на проект «Заметки с форматированием»

---

## 1. Что это вообще такое

Я делаю приложение для заметок. Пользователь может создавать заметки, форматировать текст (жирный, курсив, цвет и т.д.), сохранять их и открывать снова. Заметки хранятся и на компьютере, и на сервере.

Заметкой можно поделиться с другим пользователем. Но не просто так, а с правами - либо он может только смотреть, либо может ещё и редактировать.

Приложение состоит из двух частей: клиент с окном на PyQt и сервер на FastAPI.

---

## 2. Что должно уметь приложение

### 2.1. Пользователи

- Регистрация по логину и паролю.
- Вход в систему.
- Пароль хранится не как есть, а захешированный.
- После входа клиент получает токен и с ним ходит на сервер.

### 2.2. Заметки

- Создать заметку (заголовок + текст).
- Отредактировать её.
- Удалить (только свою).
- Увидеть список всех заметок, к которым есть доступ - и своих, и тех, какими поделились другие.

Про форматирование: нужны жирный, курсив, подчёркивание, размер шрифта и цвет.

### 2.3. Совместный доступ

- Владелец заметки может дать доступ другому пользователю, введя его логин.
- Роль выбирается: `view` (только смотреть) или `edit` (смотреть и менять).
- Доступ можно потом отозвать или поменять.
- На клиенте, если роль `view`, редактор просто блокируется (read-only) и кнопки сохранения не работают.

### 2.4. Локальное хранение и синхронизация

- Заметки хранятся в локальной базе (SQLite) на компьютере.
- Есть кнопка «Синхронизировать» - она отправляет изменения на сервер.
- Если сервер недоступен, можно работать с локальной копией, а синхронизировать потом.
- Если одну и ту же заметку поменяли в двух местах - побеждает тот, кто сохранил позже (по времени изменения).

## 3. Как это устроено внутри

### 3.1. Что где лежит

- **Сервер:** папка `server/`, внутри `main.py` (запуск), `database.py` (подключение к базе), `models.py` (таблицы), `auth.py` (токены и пароли), папка `routes/` с файлами `users.py` и `notes.py`.
- **Клиент:** папка `client/`, внутри `main.py` (запуск), `api.py` (запросы к серверу), `local_db.py` (локальная база), `workers.py` (потоки для запросов).

### 3.2. Таблицы в базе

**User** — пользователи:

| Поле | ? |
|------|---------|
| id | номер пользователя |
| username | логин |
| password_hash | хеш пароля |

**Note** — заметки:

| Поле | ? |
|------|---------|
| id | номер заметки |
| is_local | локальная ли заметка |
| owner_id | владелец (id пользователя) |
| title | заголовок |
| body_html | текст заметки в HTML |
| updated_at | когда последний раз меняли |

**Access** — доступы к заметкам:

| Поле | ? |
|------|---------|
| id | номер записи |
| note_id | к какой заметке доступ |
| user_id | кому доступ |
| role | `view` или `edit` |

В локальной БД будет только **Notes**

### 3.3. Какие запросы понимает сервер

| Что делает | Метод и адрес | Кто может |
|-----------|---------------|-----------|
| Регистрация | `POST /register` | все |
| Вход | `POST /login` | все |
| Список заметок | `GET /notes` | вошедшие |
| Создать заметку | `POST /notes` | вошедшие |
| Прочитать заметку | `GET /notes/{id}` | у кого есть доступ |
| Изменить | `PUT /notes/{id}` | владелец или `edit` |
| Удалить | `DELETE /notes/{id}` | только владелец |
| Поделиться | `POST /notes/{id}/share` | только владелец |
| Посмотреть, с кем поделились | `GET /notes/{id}/access` | только владелец |
| Отозвать доступ | `DELETE /notes/{id}/share/{user_id}` | только владелец |

## 4. Как выглядит окно

**Окно входа.** Поля логина и пароля, кнопки «Войти» и «Зарегистрироваться». Если что-то не так - показывается сообщение об ошибке.

**Главное окно.** Слева список заметок (свои и расшаренные, с пометкой роли). Справа сверху поле заголовка, под ним большой редактор текста. Над редактором панель форматирования. Внизу кнопки: новая, сохранить, удалить, поделиться, синхронизировать.

**Окно «Поделиться».** Поле для логина, выбор роли, список тех, кому уже дали доступ, с кнопкой отзыва.

Если роль `view` - редактор серый и не редактируется, кнопки сохранения и удаления неактивны.
